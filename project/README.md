# TaskFlow

Система управления задачами с ролевой моделью доступа, реализованная в виде трёхзвенной архитектуры и развёрнутая через Docker Compose.

---

## Архитектура

```
┌──────────────────┐     HTTP/JSON     ┌──────────────────┐     SQL      ┌──────────────────┐
│   Клиент         │ ─────────────────▶│  Сервер приложен.│ ────────────▶│  Сервер БД       │
│  (Браузер + SPA) │◀───────────────── │  FastAPI / Python│◀──────────── │  PostgreSQL 16   │
│  nginx :80       │                   │  uvicorn :8000   │              │  :5432           │
└──────────────────┘                   └──────────────────┘              └──────────────────┘
```

### Звенья системы
| Звено | Технология | Порт | Описание |
|-------|------------|------|---------|
| Клиент | HTML/CSS/JS + Nginx | 80 | SPA в браузере, проксирование API через Nginx |
| Сервер приложений | FastAPI + Uvicorn | 8000 (внутр.) | REST API, бизнес-логика, JWT-аутентификация |
| Сервер БД | PostgreSQL 16 | 5432 (внутр.) | Персистентное хранение пользователей и задач |

### Обоснование выбора технологий

**Протокол HTTP REST (вместо gRPC/WebSocket):**
- Наиболее распространённый и понятный протокол для веб-приложений
- Нативная поддержка в браузере через `fetch` без дополнительных библиотек
- Автоматическая генерация OpenAPI/Swagger документации из FastAPI
- Stateless — легко масштабировать горизонтально

**FastAPI (Python):**
- Автоматическая генерация Swagger UI (`/api/docs`) и ReDoc (`/api/redoc`)
- Встроенная валидация через Pydantic
- Асинхронная поддержка, высокая производительность
- Простая интеграция с SQLAlchemy

**PostgreSQL:**
- Реляционная СУБД — задачи и пользователи имеют чёткую структуру и связи (FK)
- ACID-совместимость, надёжное хранение
- Нативная поддержка Enum-типов (роли, статусы задач)
- Широко используется в production-окружениях

## Быстрый старт

```bash
# Клонировать / распаковать проект
cd taskflow

# Запустить все сервисы
docker compose up --build -d

# Создать тестовых пользователей
curl -X POST http://localhost/api/seed

# Открыть приложение
open http://localhost

# Открыть Swagger документацию
open http://localhost/api/docs
```

## API

Полная документация доступна через Swagger UI: `http://localhost/api/docs`

### Аутентификация

```http
POST /api/auth/register
Content-Type: application/json

{ "username": "user", "email": "user@example.com", "password": "pass" }
```

```http
POST /api/auth/login
Content-Type: application/x-www-form-urlencoded

username=admin&password=admin123

→ { "access_token": "...", "token_type": "bearer" }
```

Далее все запросы с заголовком:
```
Authorization: Bearer <access_token>
```

### Основные эндпоинты

| Метод | Путь | Роль | Описание |
|-------|------|------|---------|
| GET | `/api/auth/me` | все | Текущий пользователь |
| GET | `/api/tasks` | все | Список задач |
| POST | `/api/tasks` | admin, moderator | Создать задачу |
| PATCH | `/api/tasks/{id}` | все* | Обновить задачу |
| DELETE | `/api/tasks/{id}` | admin | Удалить задачу |
| GET | `/api/users` | admin | Список пользователей |
| PATCH | `/api/users/{id}` | admin | Изменить роль |
| DELETE | `/api/users/{id}` | admin | Удалить пользователя |

*viewer может обновить только статус назначенной ему задачи

### Коды ответов
| Код | Значение |
|-----|---------|
| 200 | Успех |
| 201 | Создано |
| 204 | Удалено (без тела) |
| 400 | Некорректные данные |
| 401 | Не аутентифицирован |
| 403 | Нет прав доступа |
| 404 | Не найдено |

## Управление

```bash
# Остановить
docker compose down

# Остановить и удалить данные БД
docker compose down -v

# Посмотреть логи
docker compose logs -f backend

# Пересобрать backend после изменений
docker compose up --build -d backend
```
